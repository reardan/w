# U4.2: OpenAPI generation

Part of w-orm ([#754](https://github.com/reardan/w/issues/754),
[orm.md](../orm.md)). The drf-spectacular equivalent of plan section 7:
an OpenAPI 3.0.3 document generated from U3.4's serializers, filter sets
and paginators. HTTP-agnostic and independent of the viewset layer: U4.1
describes its routes with the plain `orm_api_route` below and serves
`orm_openapi_render(api)` at `/openapi.json`.

## What landed

| File | What |
| --- | --- |
| `libs/standard/orm/rest/openapi.w` | `orm_api` / `orm_api_route` (the route description), `orm_openapi_document` (JSON tree), `orm_openapi_render` / `orm_json_pretty` (pretty text). |
| `libs/standard/orm/rest/orm_openapi_test.w` | `orm_openapi_test` (x64, no database). |
| `tests/orm/openapi/library.golden.json` | The rendered document for the fixture API. |

`orm_openapi_test` builds a four-route API over the library fixture
(`/books` full CRUD + filters + cursor pages + session/token auth +
history, `/authors/` with a write-only field, a pk list and page
numbers, `/tags` read-only with limit/offset and anonymous access,
`/catalog` with a second, named Book serializer nesting Author), then:
compares the rendering with the golden byte for byte (and renders twice
to prove determinism); parses it back and checks the required top-level
keys, that every `$ref` resolves, that operationIds are unique, that every
`{param}` in a path is a declared required path parameter and that every
`required` list is non-empty and names declared properties; spot-checks
the generated shapes; checks the configuration errors. When `python3`
can import `openapi_spec_validator` it validates the whole document;
otherwise, with `jsonschema` (what this machine has), every component
schema is checked against the Draft 4 meta-schema; with neither it prints
SKIP. Regenerate the golden with
`ORM_OPENAPI_WRITE_GOLDEN=1 bin/orm_openapi_test` (a mismatch writes
`bin/orm_openapi_test.actual.json`).

## The route description (what U4.1 fills in)

```
orm_api* api = orm_api_new(c"Library API", c"1.0.0")   # api.description optional
orm_api_route* r = orm_api_add(api, c"/books", book_serializer)
orm_api_route_actions(r, ORM_API_ALL)          # default; ORM_API_READ_ONLY = list + retrieve
orm_api_route_filters(r, filter_set)           # 0 = no filter params
orm_api_route_paginator(r, paginator)          # 0 = plain array
orm_api_route_auth(r, ORM_API_AUTH_SESSION | ORM_API_AUTH_TOKEN)   # | ORM_API_AUTH_ANON
orm_api_route_history(r, 1)                    # GET <detail>/history
orm_api_route_name(r, c"books")                # operationId prefix (default: from path)
orm_api_route_tag(r, c"books")                 # default: the name
orm_api_route_detail_path(r, c"/books/{id}")   # default: path + "/{<pk>}" ("/a/" -> "/a/{id}/")
```

`orm_api_route` is a plain struct with those fields (`path`,
`detail_path`, `name`, `tag`, `serializer`, `filters`, `paginator`,
`actions`, `auth`, `history`). Actions are `ORM_API_LIST`, `_CREATE`
(collection path), `_RETRIEVE`, `_UPDATE`, `_PARTIAL_UPDATE`,
`_DESTROY` (detail path). Several routes may share a path. Other knobs:
`orm_api_name(api, ser, "CatalogBook")` names a serializer's schema
(default: the model name, numbered on a clash);
`orm_api_field_schema(api, ser, field, json)` replaces one field's
schema (method fields are untyped otherwise); `api.session_cookie`
(`sessionid`), `api.csrf_header` (`X-CSRFToken`), `api.token_header`
(`Authorization`), `api.token_prefix` (`Token`). `orm_api_free` frees
the description, not the serializers, filters or paginators.

## What is generated

- **Schemas** (sorted by name): `<Name>` is the output, every non
  write-only entry in serializer order, all required (the serializer
  always emits every key), read-only ones `readOnly`. `<Name>Request` is
  the input (model fields that are not read-only; `required` from
  `orm_ser_field_required`; `minLength: 1` on text that may not be blank;
  write-only ones `writeOnly`), emitted only when it differs from the
  output (otherwise the output schema is reused). `Patched<Name>Request`
  is the same with nothing required, for PATCH.
- **Field kinds**: int `integer` (bigint `int64`), bool `boolean`, text
  `string` + `maxLength`, decimal `string`/`decimal` with a digits/places
  `pattern` (`number`/`double` with `decimals_as_numbers`), float
  `number`/`double`, datetime `date-time`, date `date`, UUID `uuid`, JSON
  `{}`, enum inline `enum` (plus `null` when nullable), FK the target pk
  schema. `ORM_F_NULL` gives `nullable: true`. Source fields take the
  terminal column's schema, nullable when any FK on the way is. Nested FK:
  `allOf: [$ref]`, `readOnly`; nested many: array of `$ref`; pk lists:
  array of the target pk; annotations: typed by their kind, nullable;
  method fields: `{readOnly: true}` unless overridden.
- **List envelopes**: `Paginated<Name>List` (`count`, `next`,
  `previous`, `results`) for page-number and limit/offset,
  `CursorPaginated<Name>List` (no `count`) for cursors; unpaginated lists
  are plain arrays.
- **Parameters**: one per allowed lookup (`path` for `exact`,
  `path__lookup` otherwise) in declaration order: comma lists (`in`,
  `range` with exactly two items) as `style: form, explode: false`
  arrays, `isnull` boolean, text lookups string, others the value's type
  (decimals as `number`). Then `ordering` (array of `f`/`-f` enums),
  `search`, and the paginator's params (`page` / `limit`+`offset` /
  `cursor`, plus the client page-size param with its maximum).
- **Responses**: 200/201/204 bodies; `400` (`ValidationError`) on
  create/update/patch and on filtered lists; `401` and `403` when the
  route has session or token auth; `404` on detail operations and on
  page-number/cursor lists (invalid page or cursor). Error bodies are
  shared `components/responses` over the `Error` (`{"detail"}`) and
  `ValidationError` (`{"field": [...], "non_field_errors": [...]}`)
  schemas.
- **Security**: `cookieAuth` (apiKey in cookie) + `csrfToken` (apiKey
  header) and `tokenAuth` (apiKey `Authorization` header, prefix
  `Token`), only the ones used. Each operation lists its alternatives;
  unsafe methods require the CSRF header with the cookie; anonymous
  routes add `{}`. Routes without auth have no `security`.
- **History**: `GET <detail>/history` returns an array of
  `Historical<Name>`: the serializer's model-field outputs (not
  write-only, not `ORM_F_NO_HISTORY`) plus the C8 columns `history_id`,
  `history_date`, `history_type` (`+ ~ -`), `history_user_id`,
  `history_reason`, `history_context_id`.
- operationIds are `<name>_<action>` (`books_list`, `books_create`,
  `books_retrieve`, `books_update`, `books_partial_update`,
  `books_destroy`, `books_history`), numbered `_2`... on a clash.

## Decisions

- Deterministic output: component schemas are sorted by name, every
  other object keeps insertion order (W maps iterate in insertion order),
  and the pretty printer is fixed (two spaces, `": "`, trailing newline).
- Response schemas list every emitted key as required, since the
  serializer never omits keys (null is emitted instead); nullability is
  explicit.
- Enums are inline rather than `<Name>Enum` components: no naming
  collisions, and OpenAPI 3.0 forbids siblings next to `$ref`.
- Configuration errors (serializer or filter-set errors, a history route
  on a model without history, a model without a pk) are reported by
  `orm_api_error(api)`; the document is still produced.

## Limits

- Datetimes are declared `date-time`, but U3.4 outputs
  `YYYY-MM-DD HH:MM:SS` (no `T`/`Z`) — strict clients will want U3.4 to
  emit RFC 3339.
- Field defaults (`default_sql`) and descriptions are not emitted.
- The history route is a plain array; if U4.1 paginates it, it should
  add a paginator to the description.
- Only `application/json` bodies; no servers block (set by whoever
  serves the document).
