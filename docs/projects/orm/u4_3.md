# U4.3: web base (routing, middleware, templates, forms)

Part of w-orm ([#754](https://github.com/reardan/w/issues/754),
[orm.md](../orm.md)), plan section 9. A thin MVC layer over
`libs/standard/web/http_server.w` (unchanged) that reuses U3.1 users,
U3.2 sessions / CSRF and U3.4 serializers.

## What landed

| File | What |
| --- | --- |
| `libs/standard/orm/web/router.w` | `orm_web_request`, path patterns with typed params, method routing, named routes and `orm_reverse`, mounts, includes, form-body parsing (urlencoded and multipart), response helpers. |
| `libs/standard/orm/web/middleware.w` | `orm_web_app` (router + middleware chain), request-scoped db, session, auth, CSRF and security-header middleware, login / logout helpers, `orm_web_render`. |
| `libs/standard/orm/web/templates.w` | Template engine: autoescaping, filters, if / for / include / extends, `{% url %}`, `{% csrf_token %}`, row lookups through descriptors; directory loader with a cache. |
| `libs/standard/orm/web/forms.w` | `orm_form`: ModelForm over a serializer, binding, validation, save, HTML rendering. |
| `libs/standard/orm/web/client.w` | In-process test client with a cookie jar (no socket). |
| `libs/standard/orm/web/orm_web_cases.w` | The library test app and its scenarios. |
| `tests/orm/templates/` | Template fixtures. |

Tests (`arch_only=x64`): `orm_web_template_test` (no database: templates
and routing), `orm_web_test` (SQLite in memory: the app through the
in-process client with statement counts, plus one request over a real
loopback socket), `orm_web_postgres_test` / `orm_web_postgres_local_test`
(same scenarios on PostgreSQL with a pooled per-request connection
source; the local target skips as root).

## API

**Routing** (`router.w`): `orm_router_new`, `orm_router_add(rt, "GET,POST",
pattern, handler, ctx, name)` (`_get`, `_post`), `orm_router_mount(rt,
prefix, fn, target)` with `fn(target, orm_web_request*, tail) ->
ServerResponse*` (U4.1's viewset dispatch shape), `orm_router_mount_raw`
(same with the bare `ServerRequest*`), `orm_router_include(rt, prefix,
sub, ns)`, `orm_route_csrf_exempt(route)`, `orm_router_error(rt)`.
Converters `<int:x>`, `<slug:x>`, `<str:x>` (default), `<path:x>`;
values are percent-decoded. First matching route that accepts the method
wins; GET routes accept HEAD (body dropped). Only other methods match ->
405 with `Allow`; nothing -> 404. Mount tails keep a leading `/` as
U4.1's `orm_rest_dispatch` expects (`/api/` + `/api/books/3/` ->
`/books/3/`; the prefix alone -> `""`). `orm_reverse(rt, name, params)`,
`orm_reverse0/1/1_int`: every parameter required, no extras, checked
against its converter, percent-encoded; `"ns:name"` inside namespaced
includes. Handlers are `fn(orm_web_request*, ctx) -> ServerResponse*`.

Request helpers: `orm_web_param`, `orm_web_param_int`, `orm_web_query_get`,
`orm_web_form` / `orm_web_form_get` (U3.4 `orm_params`, parsed once from
`application/x-www-form-urlencoded` or `multipart/form-data` via
`libs/standard/email/message.w`), `orm_web_upload_get` (multipart file
parts), `orm_web_header`, `orm_web_current()` (for code behind a raw
mount). Responses: `orm_web_html`, `_text`, `_json`, `_redirect`,
`_not_found`, `_forbidden`, `_method_not_allowed`, `orm_web_set_header`.

**App and middleware** (`middleware.w`): `orm_web_app_new(router)`,
`orm_web_app_use(app, fn, ctx)`, `orm_web_app_templates(app, dir)`,
`app.not_found` (custom 404), `app.secure`, `orm_web_app_handle(app,
ServerRequest*)` and the `server_handler_fn` adapter
`orm_web_app_server_handler`. A middleware calls `orm_web_next(r)`; the
route is resolved before the chain so middleware sees `r.route`.
Recommended order: security, db, session, auth, CSRF.

- `orm_web_db_middleware(source)`: `orm_web_db_source_new(open_fn, ctx)`
  (factory; up to `max_idle` connections reused) or
  `orm_web_db_source_shared(db)`. Each request gets `r.db` inside a
  transaction (Django's `ATOMIC_REQUESTS`): committed for responses below
  500, rolled back for 5xx or after `orm_web_fail(r)`; a failed commit
  becomes a 500. No connection -> 503. A transaction left open by a
  handler is rolled back on release.
- `orm_web_session_middleware`: `session_load` from the cookie or an
  unsaved anonymous session (no row until it holds data, e.g. a CSRF
  secret); afterwards creates, saves, re-sends (rotated key) or deletes
  (flushed) the cookie; adds `Vary: Cookie`.
- `orm_web_auth_middleware`: `r.user` from `session_user` (one query),
  per-request permission cache. `orm_web_login(r, user)`,
  `orm_web_logout(r)`, `orm_web_login_required(r, login_url)` (redirect
  with `?next=`), `orm_web_has_perm(r, perm)`.
- `orm_web_csrf_middleware(orm_web_csrf_config_new())`: U3.2
  `csrf_check_session` for unsafe methods on resolved, non-exempt routes;
  token from `X-CSRFToken` or the `csrfmiddlewaretoken` field; failures
  are 403 `Forbidden (<Django reason>)`. `orm_web_csrf_token(r)` gives
  the masked token (creating the secret).
- `orm_web_security_middleware(orm_web_security_new())`: nosniff,
  `X-Frame-Options: DENY`, `Referrer-Policy` and COOP `same-origin`,
  optional CSP and HSTS (HTTPS only); never overrides handler headers.
- `orm_web_context(r)` (template context with `user`, `request`, url and
  CSRF hooks) and `orm_web_render(r, name, ctx, status)` (frees ctx; a
  template error is a 500 naming it).

**Templates** (`templates.w`): `orm_tpl_engine_new(dir)`,
`orm_tpl_render(e, name, ctx)` (owned text, or 0 with
`orm_tpl_error(e)`: `name:line: message`), `orm_tpl_add` (register source),
`orm_tpl_render_string`, `orm_tpl_engine_clear`, `e.loads`. Values live in
the context arena: `orm_tpl_str/safe/int/bool/null/list/map/row/rows/result`,
`orm_tpl_set*`, `orm_tpl_put*`, `orm_tpl_push`. Syntax: `{{ a.b|filter:arg }}`,
`{% if %}/{% elif %}/{% else %}` with and/or/not and `== != < > <= >=`,
`{% for x in xs %}` with `forloop.counter/counter0/revcounter/first/last`
and `{% empty %}`, `{% include "x" %}`, `{% extends "x" %}` with
`{% block %}` (any depth), `{% url "name" k=v %}`, `{% csrf_token %}`,
`{# #}`. Filters: safe, escape, upper, lower, title, length, default,
join, linebreaksbr, truncatechars, urlencode, yesno. `orm_html_escape`
is Django's `escape`.

**Forms** (`forms.w`): `orm_form_new(model)` /
`orm_form_from_serializer(ser)`, `orm_form_set_instance`,
`orm_form_set_initial`, `orm_form_choices`, `orm_form_fk_choices(f, db,
field, label_field)`, `orm_form_bind(f, params)` /
`orm_form_bind_request(f, r)`, `orm_form_is_valid(f, db)`,
`orm_form_save(f)`, `orm_form_errors(_text)`, `orm_form_render(f,
csrf_token)` (`as_p`), `orm_form_tpl(ctx, f, csrf_token)` (template value
with `html`, `fields`, `non_field_errors`, ...).

A U4.1 viewset mounts with a four-line adapter, so the router itself
never imports the REST layer (`orm_web_cases.w` does this and the tests
call it):

```w
ServerResponse* rest_mount(void* vs, orm_web_request* r, char* tail):
	orm_rest_env env
	env.db = r.db
	env.is_secure = r.is_secure
	env.remote_addr = 0
	return orm_rest_dispatch_env(cast(orm_viewset*, vs), r.req, tail, &env)

orm_route_csrf_exempt(orm_router_mount(rt, c"/api/books", rest_mount, vs))
```

The viewset then runs on the request's connection and transaction and
does its own session / token authentication and CSRF check (hence the
exemption).

## Decisions

- **Forms share the serializer, not just its messages.** Binding builds
  the serializer's JSON input and validation is
  `orm_serializer_validate_json`; the test asserts the form's error JSON is
  byte-identical to the serializer's for the same input. Mapping from
  form text: `""` is null for nullable fields, absent for other non-text
  fields ("This field is required."), kept for text ("may not be
  blank"); absent checkboxes are false. Absent optional fields keep their
  current value on edit, as a REST PUT does.
- **Saves run in a savepoint** (`orm_atomic`), so a unique violation on
  PostgreSQL leaves the request transaction usable (the PostgreSQL test
  runs a COUNT and the session save after one).
- **Templates are runtime, Django-style, not W template strings**: the
  brief needs templates loaded from a directory and cached, which
  compile-time template strings cannot do. Escaping is always on;
  `upper`/`lower` drop safeness and `escape` does not double-escape (as
  Django). Null and missing values print as `""` (Django prints `None`
  for None).
- **Templates never query.** An FK that was not `select_related` is
  null, M2M / reverse lists are what `prefetch_related` filled, so N+1
  stays visible in the view. `<fk>_id` and `pk` always work.
- The route is resolved before middleware runs, so 404/405 responses
  still pass through the db / session middleware (one BEGIN/COMMIT) but
  skip CSRF.
- `orm_web_request` carries db / session / user typed; mounts receive it
  whole so a viewset can use the same session and user.

## Limits

- One app-level template engine; no template inheritance of `block.super`,
  no custom filters or tags, no `with` / `cycle` / `now`.
- Multipart is buffered (http_server reads whole bodies); uploads are
  kept on the request but no model kind stores files.
- No `APPEND_SLASH` redirect, no messages framework, no per-view method
  classes; HEAD drops the body (Content-Length 0).
- Session cookies use U3.2's settings (`Secure` by default), so a real
  browser on plain HTTP will not send them back; tests use the
  in-process client.
