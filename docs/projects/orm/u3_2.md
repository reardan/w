# U3.2: sessions, API tokens, CSRF, login throttle

Part of w-orm ([#754](https://github.com/reardan/w/issues/754),
[orm.md](../orm.md)). Builds on U3.1 ([u3_1.md](u3_1.md)): database
sessions with hashed keys, named API tokens, Django-compatible CSRF
tokens and an in-memory login throttle.

## Schema

| Model | Columns |
| --- | --- |
| Session | id, session_key(64) unique (SHA-256 hex of the cookie value), user_id int indexed default 0 (0 = anonymous), session_data text (JSON object of strings), expire_date indexed, created |
| ApiToken | id, user_id indexed, name(100), token_key(8) indexed (first 8 characters of the raw token), digest(64) unique (SHA-256 hex), created, expiry null, last_used null; unique (user_id, name) |

`bin/orm_gen` has no cross-file references, so `user_id` is a plain int
holding `auth_user.id`, not an FK to auth.orm's User: there is no
database cascade, so call `session_flush_user` / `token_revoke_all` when
deleting a user. The tables are not Django's (`django_session` stores
the raw key and signed pickled/JSON data), so sessions are not shared
with a Django app; CSRF tokens are.

## API

Clock and helpers (`session.w`): `auth_now()` (Unix seconds),
`auth_set_clock(fn() -> int)` (0 = real clock), `auth_time_text(t)`,
`auth_parse_time(text)`, `auth_token_digest(raw)` (owned hex SHA-256).

Sessions (`session.w`); `auth_session` holds `id`, `key` (the raw cookie
value), `user_id`, `expires_at`, `data` (string map), `modified`:

- `session_settings()`: `max_age` (1209600), `refresh_after` (300; -1 =
  no sliding), `cookie_name` ("sessionid"), `cookie_path` ("/"),
  `cookie_domain` (0), `secure` (1), `http_only` (1), `same_site` ("Lax").
- `session_create(db, user_id)`: one INSERT. Key = 32 CSPRNG bytes as
  43 urlsafe characters.
- `session_load(db, raw)`: one SELECT; 0 for unknown, malformed (checked
  before any query) or expired keys. When at least `refresh_after`
  seconds passed since the expiry was written, one UPDATE extends it to
  now + `max_age` (sliding).
- `session_get/set/remove/has`; `session_save(db, s)`: one UPDATE of data
  and expiry when modified, nothing otherwise.
- `session_rotate(db, s)`: new key, same row and data (one UPDATE).
- `session_login(db, s, user)`: s 0 → new session (INSERT); s owned by
  another user → flush + new (DELETE + INSERT); else rotate key and set
  user_id (one UPDATE), keeping data. The CSRF secret is always dropped.
  Returns the session to use.
- `session_flush` / `session_logout`: one DELETE, s becomes empty.
- `session_user(db, s)`: the active user or 0 (one SELECT).
- `session_flush_user(db, user_id)`, `session_clear_expired(db)`.
- `session_cookie_header(s)` → `sessionid=<key>; Path=/;
  Max-Age=<remaining>; Secure; HttpOnly; SameSite=Lax` (via
  `web/cookies.w`); `session_cookie_delete_header()` (Max-Age=0);
  `session_cookie_value(cookie_header)`.

API tokens (`token.w`):

- `token_create(db, user_id, name, ttl)` / `token_create_row(..., &row)`:
  one INSERT; returns the raw 43-character token once. ttl <= 0 = no
  expiry. Duplicate name per user fails on the unique constraint.
- `authenticate_token(db, raw)`: SELECT by prefix, constant-time digest
  compare over every candidate, expiry check, UPDATE `last_used` only
  when older than `token_touch_interval()` (default 60 s,
  `token_set_touch_interval`), SELECT the user (must be active). 3 queries,
  2 within the interval; failures leave `AUTH_INVALID_TOKEN()`.
- `token_lookup`, `token_list(db, user_id)`, `token_revoke(db, user_id,
  name)`, `token_revoke_raw(db, raw)`, `token_revoke_all(db, user_id)`,
  `token_clear_expired(db)`.

CSRF (`csrf.w`), Django's algorithm with the secret in the session
(`CSRF_USE_SESSIONS`, key `_csrftoken`):

- `csrf_get_secret(s)` (creates; save the session), `csrf_rotate(s)`,
  `csrf_token(s)` (fresh masked 64-character token per call),
  `csrf_mask` / `csrf_unmask`, `csrf_token_matches(secret, token)`
  (masked or bare 32-character secret; constant-time).
- `csrf_method_is_safe` (GET/HEAD/OPTIONS/TRACE), `csrf_method_needs_check`.
- `csrf_origin_ok(origin, host, is_secure, trusted)`,
  `csrf_referer_error(referer, host, trusted)`; trusted origins are exact
  (`https://app.example.org`) or wildcards (`https://*.example.net`, which
  also matches `example.net`).
- `csrf_check(secret, csrf_request*, trusted)` /
  `csrf_check_session(s, r, trusted)`: 0 or a `CSRF_REASON_*()` text.
  Order as Django: safe method passes; Origin verified when present,
  else HTTPS requires a good https Referer; then the token.

Throttle (`throttle.w`):

- `throttle_new(limit, window)`: fixed windows per key opened by the
  first failure; `throttle_fail`, `throttle_allowed`, `throttle_failures`,
  `throttle_retry_after`, `throttle_reset`, `throttle_prune` (also run when
  a table passes 4096 keys), `throttle_clear`, `throttle_free`.
- `login_throttle_new(user_limit, addr_limit, window)`;
  `authenticate_throttled(db, t, username, password, addr)`: a locked
  username or address is refused with `AUTH_THROTTLED()` before any query
  or hash; `AUTH_INVALID_LOGIN` rejections count against both keys
  (database errors do not); a success clears only the username.
  `login_throttle_allowed / retry_after / reset / is_locked(db)`.

## Limits

- The throttle is per process and in memory; several workers each keep
  their own counters.
- `csrf_check` returns Django's reason texts without the offending URL.
- Origin comparison is textual (lower-cased scheme://netloc); a default
  port written out (`https://example.com:443`) does not match
  `example.com`.
- Tables come from hand DDL in tests until the U2.4 applier lands.
- Session data values are strings only; non-string JSON members are
  dropped on load, and data that does not parse loads as empty.
