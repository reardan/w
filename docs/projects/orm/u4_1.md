# U4.1: viewsets, routing, permissions, throttling

Part of w-orm ([#754](https://github.com/reardan/w/issues/754),
[orm.md](../orm.md)), plan section 7. DRF's view layer over
`libs/standard/web/http_server.w`: ModelViewSet-style CRUD routes, a
router, DRF's authentication and permission classes over U3.1/U3.2, token
bucket throttles, a history route over U3.3, and the OpenAPI description
U4.2 renders.

## What landed

| File | What |
| --- | --- |
| `libs/standard/orm/rest/viewset.w` | `orm_viewset`, dispatch, `orm_rest_router` (in process and mounted on http_server), route description, `/openapi.json`, `orm_rest_history_json`, in-process request helpers. |
| `libs/standard/orm/rest/permissions.w` | `orm_rest_request` (per-request state), authenticators (session + CSRF, token, custom), permission trees and DRF's built-in classes. |
| `libs/standard/orm/rest/throttle.w` | `orm_throttle`: in-memory token buckets with an injectable clock. |
| `tests/orm/orm_rest_cases.w` | Shared scenarios. |
| `libs/standard/orm/rest/orm_rest_test.w` | SQLite in memory: the scenarios in process, then the same router served over loopback. |
| `libs/standard/orm/rest/orm_rest_postgres_test.w` | The scenarios on PostgreSQL (`orm_rest_postgres_local_test` starts a cluster through `bin/sql_postgres_fixture`; skips as root). |

The scenarios create the library schema (with `library_book_history`)
through `orm_makemigrations` + `orm_migrate_apply` over the generated
`tests/orm/generated/library_orm*` (as U3.3's tests do) and the auth and
session tables from U3.2's hand DDL. Key requests assert their statement
counts.

## API

```w
orm_viewset* vs = orm_viewset_new(Book_desc(), db, books_qs, ctx)   # get_queryset required
orm_viewset_serializer(vs, ser)            # default: orm_serializer_new(model), owned
orm_viewset_write_serializer(vs, ser)      # input for create/update
orm_viewset_action_serializer(vs, c"list", ser)
orm_viewset_filter(vs, fs)                 # U3.4 filter set (also applied to detail lookups, as DRF)
orm_viewset_paginator(vs, p)               # U3.4 paginator; its params are reserved in fs
orm_viewset_clear_authenticators(vs); orm_viewset_authenticator(vs, orm_auth_token())
orm_viewset_permission(vs, orm_perm_or(orm_perm_is_admin_user(), orm_perm_read_only()))
orm_viewset_throttle(vs, orm_throttle_parse(c"100/min"))
orm_viewset_actions(vs, ORM_VS_READ_ONLY)  # ORM_VS_LIST|CREATE|RETRIEVE|UPDATE|PARTIAL_UPDATE|DESTROY
orm_viewset_hooks(vs, on_save, on_delete, ctx)   # perform_create/update/destroy; orm_rest_fail(r, status, detail)
orm_viewset_history(vs, orm_rest_history_json, ser_or_0)
orm_rest_action* a = orm_viewset_action(vs, c"publish", c"POST", 1, fn, ctx)   # @action(detail=True)
orm_rest_action_permission(a, orm_perm_is_admin_user())

ServerResponse* orm_rest_dispatch(vs, ServerRequest* req, char* path_tail)   # the plain entry point
ServerResponse* orm_rest_dispatch_env(vs, req, tail, orm_rest_env*)          # + db, is_secure, remote_addr

orm_rest_router* rt = orm_rest_router_new()
orm_rest_router_register(rt, c"/api/books", vs)    # 0 + rt.error when refused
orm_rest_router_openapi(rt, c"/openapi.json", c"Library API", c"1.0.0")
orm_rest_router_mount(rt, server)                  # server_route("*", prefix + "*") per viewset
orm_rest_router_dispatch(rt, req)                  # in process
orm_rest_register(server, c"/books", vs)           # one-viewset shorthand
list[orm_rest_route*] orm_viewset_routes(vs, prefix) / orm_rest_router_routes(rt)
orm_api* orm_rest_router_api(rt, title, version)   # U4.2 description; orm_rest_api_free

ServerRequest* orm_rest_request_build(method, c"/api/books/?page=2", body)    # in-process client
orm_rest_request_header(req, c"Authorization", c"Token ...")
```

Callbacks receive `orm_rest_request* r`: `r.db`, `r.user` (`User*` or 0),
`r.session`, `r.action`, `r.method`, `r.pk`, `r.params`, `r.http` (the
`ServerRequest`), `r.object` (detail routes), `r.ctx`.

Routes: `<prefix>/` GET list / POST create; `<prefix>/<pk>/` GET, PUT,
PATCH, DELETE; `<prefix>/<pk>/history/` GET when a history callback is
set; list actions `<prefix>/<path>/` (matched before pks, as DRF's router
orders them) and detail actions `<prefix>/<pk>/<path>/`. Trailing slashes
are optional. HEAD is GET without a body, OPTIONS returns DRF's simple
metadata. Every response carries `Allow` (DRF's method order) and
`Vary: Accept`.

## Behaviour (DRF's, unless noted)

- **Order**: authenticate, check permissions, check throttles, then the
  handler; a method with no handler is 405 after those checks.
- **Authentication**: authenticators run in order, the first that
  identifies a user wins. Session: the cookie's session and active user,
  then Django's CSRF check (`X-CSRFToken`, Origin/Referer) for unsafe
  methods, failing 403 `CSRF Failed: <reason>`; anonymous sessions are
  not checked. Token: `Authorization: Token <raw>`, other schemes are
  ignored, malformed headers and bad tokens fail with DRF's messages.
- **401 vs 403**: a failed authentication, or a permission denial of an
  unauthenticated request when authenticators are configured, is
  `NotAuthenticated`: 401 with `WWW-Authenticate: <challenge>` when the
  **first** authenticator has a challenge (token: `Token`), else 403.
- **Permissions**: `orm_perm_and/or/not` with DRF's operand semantics
  (OR's object check pairs each side with its own request check),
  `orm_perm_for_actions("create,destroy", p)`, `orm_perm_message`.
  Built-ins: `allow_any`, `is_authenticated`, `is_admin_user` (=
  `is_staff`), `is_authenticated_or_read_only`, `read_only`,
  `django_model_permissions` (+ `_or_anon_read_only`, + a `view_`
  variant), `django_object_permissions` (U3.1's `user_has_obj_perm`, so
  the registered object-permission hooks decide) and
  `django_object_view_permissions` (objects the user cannot view are 404,
  as with django-guardian's perms map). Custom: `orm_perm_new(name,
  check, check_object, ctx)`.
- **404**: objects outside `get_queryset` (plus the filter set) and pks
  that do not parse as the pk type: `No <Model> matches the given query.`
  (no query for a bad pk). Unknown paths: `Not found.`.
- **400**: serializer validation and integrity errors as U3.4 maps them;
  invalid filters; JSON parse errors. 415 for a non-JSON Content-Type.
  An empty body is `{}`.
- **Writes**: create returns 201, update/patch 200, destroy 204 with an
  empty body. When the output serializer declares relations
  (source/nested/pk-list), the written row is reloaded by pk through them
  (one query) so the response is complete.
- **Throttles**: token buckets per key, `ORM_THROTTLE_USER` (user id, or
  client address when anonymous) or `ORM_THROTTLE_ANON` (anonymous only).
  Every throttle is consulted; the longest wait gives 429 with
  `Retry-After` (whole seconds, rounded up) and DRF's "Expected available
  in N seconds." text. `orm_throttle_parse("N/s|m|h|d")`,
  `orm_throttle_burst`, `orm_throttle_set_clock` (ms), `max_keys` (4096,
  then full buckets are pruned).
- **History**: `orm_rest_history_json` (U3.3 `orm_history_of`) returns
  every version newest first: the serializer's fields of that version
  (default: every model field) plus `history_id`, `history_date`,
  `history_type`, `history_user_id`, `history_reason`,
  `history_context_id`. Any callback returning JSON text can be used
  instead. For models with history, authenticated unsafe requests run
  inside `orm_history_set_context(db, user.id, "<METHOD> <path>")`,
  cleared after the request (`orm_viewset_history_context(vs, 0)` turns
  it off).
- **OpenAPI**: `orm_rest_router_api` turns each viewset into one U4.2
  `orm_api_route` (path with trailing slash, actions, filters, paginator,
  history, auth from the authenticators, `ANON` when a static reading of
  the permission tree lets anonymous requests through, name from the last
  prefix segment). The router serves it at the configured path.

## Decisions

- `orm_viewset_new` defaults to session-then-token authentication and
  `is_authenticated` (DRF's default is `AllowAny`); a viewset has to opt
  in to anonymous access.
- The dispatch signature is `ServerRequest* -> ServerResponse*` so a
  router owns nothing per request; `orm_rest_env` carries what a socket
  knows (TLS, peer address) and a request-scoped db.
- Pagination links use the request path as their base.
- Configuration objects (viewsets, permissions, authenticators,
  throttles) live for the process; permissions may be shared.

## Limits

- Extra actions are not in the OpenAPI document: `orm_api_route` has no
  slot for them (they are in `orm_viewset_routes`).
- The session cookie is never re-sent: viewsets do not log in, and a
  sliding refresh by `session_load` does not update the client's Max-Age.
- No content negotiation or browsable API; JSON only.
- Throttle state is per process and per throttle object.
- The history route is not paginated.
- `remote_addr` comes from the socket peer; there is no
  X-Forwarded-For/NUM_PROXIES handling yet.
