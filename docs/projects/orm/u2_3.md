# U2.3: safe-pattern migration planner + linter

Part of w-orm (issue #754, plan section 5.2). Depends only on contract C7
(`libs/standard/orm/contract.w`: `orm_op`, `orm_migration`, `ORM_OP_*`,
`ORM_PHASE_*`). No SQL is generated or executed here: the planner builds
op lists, the applier (U2.4) turns them into dialect SQL.

## What landed

- `libs/standard/orm/migrate/planner.w`: `orm_change` (the autodetector's
  "intent"), `orm_planner`, `orm_plan`, `orm_plan_describe`.
- `libs/standard/orm/migrate/lint.w`: `orm_lint_migration`,
  `orm_lint_plan`, findings with stable codes, plus shared helpers
  (`orm_op_kind_name`, `orm_phase_name`, the `orm_mjson_*` field_json
  reader/writer and the RAW_SQL tokenizer `orm_sql_statements`).
- Tests: `orm_planner_test` (one case per row of the 5.2 table, both
  dialects where they differ, force, interleaving, errors; every safe plan
  must also lint clean) and `orm_migrate_lint_test` (positive and negative
  cases per code, force downgrade). Both `arch_only=x64`, no database.

## Planner API

```
orm_change* c = orm_change_new(ORM_CHANGE_ADD_COLUMN, c"book", c"isbn")
c.field_json = ...            # new field snapshot
orm_planner* p = orm_planner_new(c"library", ORM_DIALECT_POSTGRES, 7, c"0006_prev")
list[orm_migration*] plan = orm_plan(p, changes)   # 0 + p.error on a bad change
char* text = orm_plan_describe(plan)
orm_planner_free(p, plan)
```

`orm_change` fields: `kind`, `table`, `column`, `new_name`, `name`
(index/constraint name, derived when 0), `field_json`, `model_json`, `sql`
(FK/CHECK body), `backfill` (registered backfill name, default
`<table>_<column>_backfill`), `nullable` (target), `has_default`, `force`,
`batch_size` (default 1000).

Naming: `NNNN_<phase>_<label>` with a 4-digit number from `next_number`;
label is `<table>_<column>`, `<table>` or `<table>_to_<new>` (table
rename). Ordering: stage k of every change ships before stage k + 1 of any
change; within a stage the input order is kept. Every migration depends on
the previous one (`app.name`, the first on `previous`). Every contract
migration sets `requires_applied` to its change's first migration (the
expand step; for `alter_null` the first step is a migrate step).
Batched data ops (`BACKFILL`, `COPY_COLUMN`, `COPY_TABLE`) are
`non_atomic = 1`, so their migrations are non-atomic.

## Sequences (section 5.2)

PG = PostgreSQL (also any non-SQLite dialect id), SL = SQLite.

| Change | Migrations |
|---|---|
| add column, nullable or with default | E: `ADD_COLUMN` |
| add column NOT NULL, no default | E: `ADD_COLUMN` (field_json `"null": true`); M: `BACKFILL`, PG `ADD_CONSTRAINT CHECK (c IS NOT NULL)` (NOT VALID); C: PG `VALIDATE_CONSTRAINT`, `ALTER_NULL` (`"null": false`), PG `DROP_CONSTRAINT` |
| alter null -> nullable | E: `ALTER_NULL` |
| alter null -> NOT NULL | M: `BACKFILL`, PG `ADD_CONSTRAINT`; C: PG `VALIDATE`, `ALTER_NULL`, PG `DROP_CONSTRAINT` |
| drop column | E: `ALTER_NULL` with `"null": true, "deprecated": true`; C: `DROP_COLUMN` |
| rename column / change type | E: `ADD_COLUMN new` (nullable, `"column"` = new), `SYNC_TRIGGER new <- old`; M: `COPY_COLUMN new <- old` (+ PG not-null check when the target is NOT NULL); *deploy: code reads/writes new*; C1: [not-null tightening of new], `ALTER_NULL old` deprecated, `DROP_SYNC_TRIGGER`; C2: `DROP_COLUMN old`. Type change: new column is `new_name` or `<column>_new` (the field keeps its name, its `column` changes). |
| rename table | E: `CREATE_TABLE new`, `SYNC_TRIGGER new <- old`; M: `COPY_TABLE`; *deploy: code uses new*; C1: `DROP_SYNC_TRIGGER`; C2: `DROP_TABLE old` |
| rebuild table | E: `CREATE_TABLE <t>__new` (or `new_name`), `SYNC_TRIGGER`; M: `COPY_TABLE`; M (atomic): `SWAP_TABLES`, `DROP_SYNC_TRIGGER`; C: `DROP_TABLE <t>__new` (now holding the old rows) |
| add index | E: `ADD_INDEX` (`non_atomic = 1` on PG: CONCURRENTLY; plain on SL). field_json gets `"columns": [column]` when absent |
| add FK / check | E: `ADD_CONSTRAINT` (NOT VALID); M (PG only): `VALIDATE_CONSTRAINT` |
| add unique | PG: E: `ADD_INDEX <name>_idx` (`"unique": true`, non_atomic); M: `ADD_CONSTRAINT <name>` sql `UNIQUE USING INDEX <name>_idx`. SL: E: unique `ADD_INDEX` only |
| create table | E: `CREATE_TABLE` |
| drop table | E: empty migration (no database change: the model is deprecated in code); C: `DROP_TABLE` |

The "deprecated" marker for drop column is an `ALTER_NULL` op whose
field_json has `"deprecated": true`: the applier only drops NOT NULL (so
new code that no longer writes the column keeps working), the generator
stops selecting/writing the field. No RAW_SQL is involved.

Rename table deviates from the plan's "swap names" wording: a rename has
no name to swap, so the deploy that switches code to the new table is the
swap; the sync trigger keeps both tables in step until C1.

`force = 1` emits the direct single-step op marked `unsafe = 1` for: add
column (NOT NULL without default), alter null -> NOT NULL, drop column,
drop table (contract op without `requires_applied`), rename table
(`RENAME_TABLE new <- old`), add index (non-concurrent). Renames and type
changes of columns and the constraint kinds have no forced form.

## Linter

`orm_lint_migration(orm_migration*, int dialect_id) -> list[orm_lint_finding*]`
(`code`, `severity` ORM_LINT_ERROR/WARNING, `message`, `op_index`, -1 for
the migration). An op with `unsafe = 1` downgrades its errors to warnings.
`orm_lint_plan`, `orm_lint_count`, `orm_lint_has`, `orm_lint_format`,
`orm_lint_free` help callers. RAW_SQL text is tokenized (comments,
string literals and quoted identifiers handled; statements split at `;`)
and the obvious `ALTER TABLE` clauses, `CREATE [UNIQUE] INDEX`,
`RENAME TABLE` and `DROP TABLE` shapes are checked with the same rules.

| Code | Severity | Rule |
|---|---|---|
| W-ORM-M001 | error | in-place table rename (`RENAME_TABLE`, `ALTER TABLE .. RENAME TO`, `RENAME TABLE`) |
| W-ORM-M002 | error | in-place column rename (RAW_SQL `RENAME [COLUMN] a TO b`) |
| W-ORM-M003 | error | in-place type change (RAW_SQL `ALTER [COLUMN] c TYPE` / `SET DATA TYPE` / `MODIFY` / `CHANGE`) |
| W-ORM-M004 | error | `ADD_COLUMN` NOT NULL without default (field_json `"null"` not `true` and no non-null `"default"`), or RAW_SQL `ADD COLUMN .. NOT NULL` without `DEFAULT` |
| W-ORM-M005 | error | PG: `ADD_INDEX` with `non_atomic = 0`, `CREATE INDEX` without `CONCURRENTLY`, `ADD UNIQUE/PRIMARY KEY` without `USING INDEX` |
| W-ORM-M006 | error | destructive op (`DROP_COLUMN`, `DROP_TABLE`, `DROP_CONSTRAINT`, `DROP_HISTORY`, RAW_SQL `DROP TABLE` / `ALTER TABLE .. DROP`) in a migration without `requires_applied` |
| W-ORM-M007 | error | destructive op in a migration that also has expand-phase ops |
| W-ORM-M008 | error | non_atomic op (or RAW_SQL `CREATE INDEX CONCURRENTLY`) in a migration with `atomic = 1` |
| W-ORM-M009 | error | `SWAP_TABLES` in a non-atomic migration |
| W-ORM-M010 | warning | PG: RAW_SQL FK/CHECK added without `NOT VALID` |
| W-ORM-M011 | warning | PG: NOT NULL set (`ALTER_NULL` `"null": false` or RAW_SQL `SET NOT NULL`) without an earlier `VALIDATE_CONSTRAINT` in the migration |

## field_json keys assumed

C7 leaves the field snapshot format open. The planner and linter read and
write only these top-level keys: `"null"` (bool; absent means NOT NULL,
matching `ORM_F_NULL`), `"default"` (present and not `null` = has a DB
default), `"deprecated"` (bool), `"column"` (string), and for ADD_INDEX
`"columns"` (array) and `"unique"` (bool). U1.1/U2.2 should emit these
names (see contract change requests in the PR).

## Limits

- No SQL parser dependency: the RAW_SQL checks are token-level and cover
  the obvious shapes only (`libs.standard.sql.parser` has no DDL grammar
  for ALTER clauses worth reusing yet).
- Dialect ids other than `ORM_DIALECT_SQLITE` plan like PostgreSQL.
- Constraint names are not truncated to PostgreSQL's 63-byte limit.
- The planner does not check that a rename target is unused or that
  `model_json` matches; the autodetector supplies consistent intents.
