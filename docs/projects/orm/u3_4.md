# U3.4: serializers, filters, pagination

Part of w-orm ([#754](https://github.com/reardan/w/issues/754),
[orm.md](../orm.md)). The DRF core of plan section 7, HTTP-agnostic:
inputs are JSON text / query strings (`orm_params`), outputs are
`structures/json.w` trees or JSON text. The viewset unit (U4.1) wires them
to `libs/standard/web/http_server.w`.

## What landed

| File | What |
| --- | --- |
| `libs/standard/orm/rest/serializer.w` | `orm_serializer` (output, declared relations, validation, save with integrity-error mapping) plus shared helpers (`orm_rest_error_add`, `orm_rest_detail`, `orm_rest_field_text`). |
| `libs/standard/orm/rest/filter.w` | `orm_params` (query-string parsing/encoding) and `orm_filter_set` (whitelisted filters, ordering, search). |
| `libs/standard/orm/rest/pagination.w` | `orm_paginator` (page number, limit/offset, cursor) and `orm_page` envelopes. |

Tests (SQLite in memory over the library fixture, `arch_only=x64`, skip
without libsqlite3): `orm_serializer_test`, `orm_rest_filter_test`,
`orm_pagination_test`. They assert exact JSON and query counts.

## API

**Serializer** (`orm_serializer_new(Model_desc())`): every column field
(deprecated ones excluded) in declaration order, FKs as the target pk
under the field name (`"author": 3`). Auto pks, `auto_now(_add)` and
`ORM_F_READ_ONLY` fields are read-only. Configuration (each returns the
serializer; a mistake sets `orm_serializer_error(ser)`):
`include(list)`, `exclude(name)`, `rename(name, out)`, `read_only`,
`write_only`, `required(name, 0/1)`, `allow_blank`,
`source(out, "author__name")` (FK chains only),
`nested(field, child)` (FK: object replacing the pk entry; M2M/reverse:
array), `pk_list(field)` (M2M/reverse as pks), `annotation(name, kind)`
(row trailer, typed by ORM kind), `method(name, fn, ctx)`,
`field_validator(name, fn, ctx)`, `validator(fn, ctx)`,
`select_related/prefetch_related(path)` (extra paths for method fields),
`decimals_as_numbers(1)`, `unknown_fields(ORM_SER_UNKNOWN_IGNORE)`.

Declared relations: `orm_serializer_prepare(ser, qs)` adds
`select_related` for every FK prefix of a source and every nested FK, and
`prefetch_related` for nested/pk-list many relations (everything below a
many relation becomes a prefetch path, `books__author`).
`orm_serializer_select_paths` / `prefetch_paths` expose the lists.

Output: `orm_serializer_to_json(ser, row)`, `_many(ser, rows)`,
`_result(ser, r)`, `_render(ser, row)`, `_render_result(ser, r)`. JSON
types: INT/BIGINT/FK ints, BOOL `true/false`, DECIMAL strings at the
field's scale (numbers with the option), FLOAT numbers, JSON fields
embedded, other text kinds strings, SQL NULL `null`. Datetimes are the
stored `YYYY-MM-DD HH:MM:SS` text.

Input: `orm_serializer_validate(ser, db, json_text, instance, partial)`
(or `_validate_json` with a parsed tree) -> `orm_validation*` (never 0):
`v.errors` (DRF shape `{"field": ["message"]}`, `non_field_errors`, or
`{"detail": ...}`), `v.status` (0, 400, 500), `v.row` (the instance, or a
new `orm_row_new` row freed with `v` unless `orm_validation_take_row`).
Checks: required/missing, null, blank, wrong type, `max_length` in code
points, decimal digits/places via `sql_decimal_fits` (DRF's three
messages), enum choices, datetime/date/UUID shape, FK pk type and
existence (one `exists()` query per FK value), unknown keys (rejected by
default), read-only keys ignored, PATCH (`partial`) skipping absent
fields, per-field validators after the type checks, the object validator
when every field passed (`orm_validation_get(v, name)` returns the
pending or current value). Nothing touches the instance unless every
check passes.

Save: `orm_validation_save(v)` or `orm_serializer_save(db, ser, row,
&status)` -> 0 or an error object. Database messages from both backends
map to fields: UNIQUE (`"<model> with this <field> already exists."`, or
a `non_field_errors` "must make a unique set" for composites), NOT NULL,
FK (PostgreSQL's `Key (col)=(v)`; SQLite names no column, so each FK of
the row is probed with one query), CHECK (the field when the
constraint's condition names exactly one column). Other failures are 500
`{"detail": message}`.

**Filters**: `orm_filter_new(m)`, `orm_filter_allow(fs, path,
"exact,gte,in")`, `orm_filter_ordering(fs, path)`,
`orm_filter_search(fs, path)`, `orm_filter_ignore(fs, param)`;
`orm_filter_apply(fs, qs, params, &errors)` -> new queryset or 0 with an
owned error object. Values are checked by field kind (whole numbers,
booleans, decimals, dates, enum choices) and `in`/`range` take comma
lists. `?search=` splits terms on whitespace/commas; every term must
icontains-match some search field. `?ordering=-a,b` replaces the
queryset ordering. Empty values and reserved params are ignored; paths
through M2M/reverse relations make the queryset `distinct`.
`orm_params_parse/get/set/add/remove/encode/url/free`.

**Pagination**: `orm_paginator_page_number(size)`,
`orm_paginator_limit_offset(limit)`, `orm_paginator_cursor(ordering,
size)`, `orm_paginator_client_size(p, "page_size", max)`,
`orm_paginator_reserve(p, fs)`; `orm_paginate(p, qs, params, "/books")`
-> `orm_page` (`result`, `count`, `next`, `previous`, `error`, `status`);
`orm_page_json/render(pg, ser)` -> `{"count", "next", "previous",
"results"}` (`count` omitted for cursors).

## Decisions

- **Cursor pagination is keyset, never counts.** The token is base64url
  (no padding) of `f|<pk>|<key>` / `r|...`; each page is one query
  `WHERE key > v OR (key = v AND pk > id) ORDER BY key, pk LIMIT n + 1`
  (directions flipped for `-key` and for previous pages, whose rows are
  reversed back). The ordering is the paginator's own (one non-null column
  plus the pk, or the pk alone): it replaces the queryset's ordering so
  links stay stable. Nullable columns are refused. Malformed tokens are
  404 `{"detail": "Invalid cursor"}`.
- Page-number and limit/offset paginate the queryset's ordering with the
  pk appended (pk alone when unordered), so pages never overlap. They cost
  a COUNT plus the page query. Out-of-range pages are 404 `Invalid page.`
  (page 1 of an empty set is valid; `page=last` works).
- Links keep the other params and replace the paging params in place;
  page 1 / offset 0 links drop the param, as DRF does.
- Unknown input keys are rejected by default (DRF ignores them); unknown
  filter params are always rejected.
- Bound filter values point into `orm_params` (and strings it owns), so
  params must outlive evaluation of the filtered queryset. Serializer
  paths are owned by the serializer, which must outlive prepared querysets.
- Nested writes are not supported (explicit, as in DRF): nested, source,
  annotation, method and pk-list fields are read-only.

## Limits

- Nested/pk-list many relations output the row's relation list slots,
  filled by U2.1's `prefetch_related` (one extra query per relation; the
  test asserts it). `Prefetch(to_attr)` lists are not serialized; they live in
  the row meta's attr lists, not among annotations (H1), and annotation
  fields still refuse names starting with `prefetch:` as a guard.
- `source` paths follow FKs only; method fields must declare any other
  relation they read with `orm_serializer_select_related/prefetch_related`.
- Decimal numbers in input/output go through the JSON tree's float, so
  `decimals_as_numbers` prints `7.0` for `7.00`; the string default is
  exact.
- Datetimes are not converted to ISO `T`/`Z` output; input accepts
  `YYYY-MM-DDTHH:MM:SS[Z]` and stores it as `YYYY-MM-DD HH:MM:SS`.
- Only SQLite end-to-end tests; the PostgreSQL error mapping is tested
  against PostgreSQL message text.
