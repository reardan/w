# U1.1: `.orm` schema files and `bin/orm_gen`

Part of the w-orm project ([orm.md](../orm.md), issue #754).

## What landed

| Path | What |
| --- | --- |
| `libs/standard/orm/schema/schema.w` | In-memory schema model (`orm_schema`, `orm_schema_model`, `orm_schema_field`, ...) and the line parser `orm_schema_parse(text, path)`. |
| `libs/standard/orm/schema/codegen.w` | `orm_codegen_data(s)`, `orm_codegen_api(s, data_module)`, `orm_codegen_schema_json(s)`, `orm_codegen_model_json(s, m)`. |
| `libs/standard/orm/schema/dump.w` | `orm_schema_dump_registry()`: canonical text of every registered descriptor (imports `contract.w`). |
| `tools/orm_gen.w` | CLI, binary `bin/orm_gen`; also owns the `orm_generated` (tag `generated`) and `orm_gen_test` targets. |
| `tests/orm/fixtures/shop.orm` | Second schema using every type and option. |
| `tests/orm/fixtures/invalid.orm` | CLI error fixture. |
| `tests/orm/fixtures/library_orm_api.golden`, `library_schema.json` | Goldens for the API module and the snapshot. |

```sh
bin/orm_gen app/models.orm -o out/        # out/<app>_orm.w, out/<app>_orm_api.w, out/<app>_schema.json
bin/orm_gen app/models.orm -o out/blog    # out/blog_orm.w, out/blog_orm_api.w, out/blog_schema.json
bin/orm_gen app/models.orm                # data module to stdout
```

`-o` is a directory when it ends in `/` or already is one (missing
directories are created). The API module imports the data module by the
dotted form of its path relative to the current directory
(`out/blog_orm.w` -> `import out.blog_orm`); `--module <dotted>` overrides
that. Errors go to stderr as `file:line: message`, all of them, and the
exit status is 1.

Generated files are not committed (issue #323): `orm_generated` writes
`tests/orm/generated/{library,shop}_*` (gitignored) before other targets
run.

## Tests

- `orm_schema_test` / `orm_schema_64_test`: parser results, dependency
  order with cycles, self relations, 37 exact error messages, and the
  snapshot/API text against the goldens.
- `orm_gen_test` (tests_x64): runs `bin/orm_gen` on `library.orm`,
  `cmp`s the data module with the `orm_generated` output and the API
  module and snapshot with the goldens, then compiles
  `tests/orm/orm_gen_dump_fixture.w` (imports the hand-written
  `tests/orm/fixtures/library_orm.w`) and
  `tests/orm/orm_gen_dump_generated.w` (imports the generated module) and
  `cmp`s their descriptor dumps. Last, the CLI error path on
  `invalid.orm`.
- `orm_gen_shop_test` (x64): the generated `shop` module compiles,
  registers, resolves, and every descriptor attribute matches the schema.

The dump covers every field of `orm_model_desc`, `orm_field_desc`,
`orm_index_desc` and `orm_check_desc` (offsets and sizes included) except
`schema_json`, which the fixture leaves 0, and `rel_target`, which is
printed as the target's model name.

## Why a hand-written parser

The plan suggested a parser-generator grammar (`orm.pg`, like `proto.pg`).
The format is line-oriented: one declaration per line, one level of tab
indentation, no nesting or expressions except the opaque SQL of `check`.
A line splitter plus a token switch is about 400 lines, needs no generated
parser file in the `generated` umbrella, and makes `file:line: message`
errors trivial and precise. A grammar would add a build step and still need
the same semantic checks.

## Format reference

```
app <name>                         # once; prefixes tables and generated globals
model <Name>:                      # top level; body indented one tab
	<type> <name> [options]        # scalar field
	enum <Name>: a, b, c           # enum type usable by later lines of this model
	<EnumName> <name> [options]    # enum field
	fk <name> -> <Model> [on_delete=...] [related_name=x] [null] [default=n] [...]
	m2m <name> -> <Model>
	index <f1> [f2 ...] [name=<n>]
	unique_together <f1> <f2> [...]
	check <sql> [name=<n>]         # sql is the raw rest of the line
	history
	table=<name>
```

`#` starts a comment outside double quotes. Option values may be double
quoted to hold spaces (`default="Main Street"`).

Types: `string` / `text` -> `ORM_TEXT` (`text` takes no `max_length`),
`int`, `bigint`, `bool`, `decimal`, `datetime`, `date`, `uuid`, `json`,
`float`, enums -> `ORM_ENUM` (text; `max_length` = longest value).

Options: `max_length=` (string), `digits=` / `places=` (decimal),
`default=`, `unique`, `null`, `indexed`, `deprecated`, `no_history`,
`read_only`, `pk` (not on fk), `auto_now` / `auto_now_add` (datetime,
date), `on_delete=` / `related_name=` (fk). Anything else is
`bad option '<x>'`.

`default=` becomes `default_sql`: text-backed kinds are quoted SQL
literals (`'draft'`, `''` escaping), ints and numbers are checked and
copied, bool `true/false/1/0` -> `TRUE`/`FALSE`, `null` -> `NULL` (needs
`null`), `now` on datetime/date -> `CURRENT_TIMESTAMP`/`CURRENT_DATE`.

Errors reported (exact texts are asserted by `orm_schema_test`): unknown
type, unknown FK/M2M target, duplicate field/model/enum/enum value
(a field also occupies `<fk>_id`), bad option, bad default, `places`
exceeding `digits`, spaces in indentation, missing `app`, `set_null`
without `null`, `set_default` without `default`, index / unique_together
naming unknown fields or relations, `related_name` clashing with a target
field, relation to a model whose pk is not int, reserved field names (W
keywords and type names), `__` in field names, relation names that clash
with API functions (`desc objects rows new save delete free`), more than
one pk, a field named `id` without `pk`.

## Generation decisions beyond orm.md

- Order: Kahn's algorithm over FKs (self FKs ignored), always taking the
  earliest-declared ready model; when only a cycle remains, the
  earliest-declared remaining model goes next. An FK slot is typed `T*`
  only when `T` is emitted earlier, else `void*` (accessors cast).
- Nullable FK `x`: `int x_id`, `T* x` (or `void*`), `int x__isnull`.
  Nullable int-backed scalar `n`: `int n` then `int n__isnull`.
- FK default `on_delete` is `protect` when the option is absent.
- M2M through table `<table>_<field>`, columns `<model>_id` and
  `<target>_id` (lower-case model names); a self M2M uses
  `from_<model>_id` / `to_<model>_id`.
- Reverse relations exist only for FKs with `related_name`. They are
  appended after the target's own fields in schema order of the FKs.
- Index default name `<table>_<columns joined by _>_idx`; columns are SQL
  columns (`author_id` for FK `author`). Unnamed checks are
  `<table>_check<N>`, N the 1-based position among the model's checks.
- `orm_model_desc.unique_together` holds column names.
- `pk` on a field drops the automatic `id`; the field gets `ORM_F_PK`
  only (no `ORM_F_AUTO`).
- Each `M_desc()` sets `m.schema_json` to the model's snapshot object.
- Field handles cover every field, reverse relations included; enum
  handles are `M_<Enum>_<value>()`.

## Schema snapshot (for the migration autodetector)

`char* <app>_schema_json()` in the data module and `<prefix>_schema.json`
(same text plus a newline) hold one compact JSON object; keys always
appear, in this order, so two snapshots can be compared field by field:

```
{"format":"w-orm-schema","version":1,"app":"<app>","models":[<model>,...]}
```

Models are in generated (FK dependency) order. Each `<model>` (also each
`orm_model_desc.schema_json`):

```
{"name":"Book","table":"library_book","history":true,
 "fields":[<field>,...],          # declaration order, auto id first, reverse relations last
 "indexes":[{"name":"...","fields":["created"],"columns":["created"],"unique":false,"condition":null}],
 "checks":[{"name":"...","sql":"price >= 0"}],
 "unique_together":[{"fields":["customer","store"],"columns":["customer_id","store_id"]}]}
```

Each `<field>`:

| Key | Value |
| --- | --- |
| `name` | field / lookup name |
| `column` | SQL column, `null` for m2m / reverse_fk |
| `kind` | the C2 `ORM_*` kind number (`ORM_TEXT` = 4, ...) |
| `kind_name` | the same kind as text: `int bigint bool text decimal datetime date uuid json fk enum m2m reverse_fk float` (the constant, lower-case, without `ORM_`) |
| `type` | the type as written: `string`, `text`, `Status`, `fk`, `m2m`, `reverse`, ... |
| `pk null unique indexed auto auto_now_add auto_now deprecated no_history read_only` | booleans, the C2 flag bits |
| `max_length digits places` | integers, 0 when unset |
| `default` | `default_sql` text or `null` |
| `enum` / `enum_values` | enum type name or `null`; its values (`[]` otherwise) |
| `rel_model` | fk / m2m target, reverse_fk source model, else `null` |
| `on_delete` | fk only: `cascade protect restrict set_null set_default do_nothing`; else `null` |
| `related_name` | fk only, or `null` |
| `through_table through_from through_to` | m2m only, or `null` |
| `reverse_field` | reverse_fk only: the FK field on `rel_model`, or `null` |

Each field object is a superset of the C7 `field_json` keys in
`contract.w` (`name column kind null default deprecated max_length digits
places unique`), and each index object carries the `name columns unique`
keys `ADD_INDEX` uses, so the autodetector can copy them into `orm_op`s.
`default` is `null` when the column has no database default.

Offsets and struct sizes are deliberately absent: they depend on the
target's word size, and the database schema does not. Strings use JSON
escapes (`\"`, `\\`, `\u00XX` for control bytes). `version` changes when a
key is added or its meaning changes.

## Limits

- Enums are model-scoped; there are no top-level enums.
- No `related_name` on m2m, no partial or unique `index` syntax (the
  descriptors support both; `orm_index_desc.unique` is always 0 here).
- FK and M2M targets must have an int pk (C2 stores FKs as `int`).
- The API module is golden-tested as text only; it compiles once the U1.3
  runtime (`libs.standard.orm.orm`) lands.
