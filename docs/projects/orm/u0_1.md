# U0.1: typed SQL values

Part of the w-orm plan (issue #754, section 2 item 1).
`libs/standard/sql/values.w` reads typed values out of a `sql_result*`
without changing `client.w`: every client still returns text, and these
helpers parse that text once. Test: `sql_values_test`
(`libs/standard/sql/sql_values_test.w`, x64 only).

## API

Cell readers return 1 and write `*out` on success. They return 0 and
leave `*out` untouched for SQL NULL, an invalid row/column, or text that
does not parse.

| Function | Accepts |
|---|---|
| `sql_value_is_null(r, row, col)` | 1 for SQL NULL (length -1) **and for an invalid index** (length -2, or `r == 0`). |
| `sql_value_int(r, row, col, int* out)` | see `sql_parse_int` |
| `sql_value_bool(r, row, col, int* out)` | see `sql_parse_bool` |
| `sql_value_decimal(r, row, col, char** out)` | valid decimal text; `*out` is borrowed until `sql_result_free` |
| `sql_value_datetime(r, row, col, datetime* out)` | see `sql_parse_datetime` |
| `sql_value_date(r, row, col, date* out)` | see `sql_parse_date` |
| `sql_parse_int(text, out)` / `sql_parse_int_n(text, len, out)` | optional `+`/`-`, then one or more ASCII digits; nothing else. Rejects values outside the word size (x64: -2^63 .. 2^63-1). |
| `sql_parse_bool(text, out)` / `sql_parse_bool_n` | `1`/`0`, `t`/`f`, `true`/`false`, any case. |
| `sql_decimal_valid(text)` | optional sign, digits, at most one `.` with a digit on each side (`-12.50`, `7`). |
| `sql_decimal_fits(text, digits, places)` | valid and fits `DECIMAL(digits, places)` without rounding (leading zeros ignored). |
| `sql_format_int(v)` | newly allocated decimal text (caller frees), including the minimum int. |
| `sql_parse_datetime(text, datetime* out)` / `sql_parse_date(text, date* out)` | `libs/standard/time/format.w`'s `datetime_fromisoformat` / `date_fromisoformat`. |
| `sql_int_min()` | the smallest word-sized int. |

## Decisions and limits

- Strict parsing: no whitespace, exponents, hex, or locale separators.
  The ORM formats what it writes, so strictness catches type mismatches.
- Decimals stay text (`ORM_DECIMAL` is text-backed); `.5`, `5.`, `NaN`
  and `Infinity` are rejected, so PostgreSQL's numeric `NaN` reads as
  invalid.
- Cell readers use the cell length, so a value with an embedded NUL (a
  blob) is rejected rather than truncated.
- Datetimes accept SQLite's `YYYY-MM-DD HH:MM:SS[.fff]` and PostgreSQL's
  `YYYY-MM-DD HH:MM:SS[.ffffff][+HH[:MM]]`; an offset makes the result
  aware. PostgreSQL `infinity`/`-infinity` and `BC` dates are rejected.
  This makes `values.w` import `libs/standard/time/format.w` (and
  through it `structures/string.w`).
- Tested against SQLite in memory (skips cleanly without libsqlite3).
  PostgreSQL's `t`/`f` and offset timestamps are covered by the text
  parser tests, not a live PostgreSQL run.
