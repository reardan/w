# U1.3: QuerySet API, loading, writes

Part of w-orm ([#754](https://github.com/reardan/w/issues/754),
[orm.md](../orm.md)). The runtime half of phase 1: querysets over the C3
query tree, row loading through the C4 column map into C6 results, and
single-row, bulk and M2M writes. SQL comes from U1.2's `orm_compile`; this
unit never builds SQL text itself.

## API

Expressions (`expr.w`), all returning new immutable nodes; string
arguments are borrowed:

- Where: `q("author__name__icontains", v)` (trailing lookup split off, bare
  path = exact, null value = IS NULL), `q_eq/ne/gt/gte/lt/lte/icontains`,
  `q_eq_int`, `q_lookup(path, lookup, v)`, `q_expr(path, lookup, expr)`,
  `q_in(path, list[char*])` (empty = matches nothing), `q_in_exprs`,
  `q_range`, `q_isnull(path, int)`, `q_bool(expr)`, `q_and/q_or` (0 is "no
  condition"; nested and/or flatten), `q_not`, `q_true/q_false`.
- Expressions: `f(path)`, `val(text)` (0 = NULL), `val_int(int)` (inlined),
  `e_null`, `e_func(name, list)`, `e_add/sub/mul/div/concat`, `e_coalesce`,
  `e_lower`, `e_upper`, `e_raw(sql, args)`, `e_outer(path)`,
  `e_case(list[orm_when*], else)`, `e_when(where, expr)`,
  `e_window(expr, partition, order)`; `e_subquery(qs)` / `e_exists(qs)` are
  in query.w.
- Aggregates: `agg_count(path)` (0 or "*" = COUNT(*)), `agg_count_distinct`,
  `agg_sum/avg/min/max`, `agg_of(name, expr)`, `agg_filter(agg, where)`.
- Ordering: `ord("-author__name")`, `ord_expr(expr, desc)`, `ord_nulls`.
- Assignments: `orm_set(field, expr)`, `orm_set_text`, `orm_set_int`.

QuerySet (`query.w`; method sugar `qs.filter(w)`): `filter`, `exclude`,
`having`, `order_by(spec)` (appends; `order_clear` resets),
`order_by_expr`, `order`, `limit`, `offset`, `slice(a, b)` (composes like
Python slices, `b < 0` = open), `distinct`, `select_related(path)`,
`prefetch_related(path)` (recorded only, executed by U2.1), `annotate`,
`values(list)`, `values_list(list)`, `only(list)`,
`for_update(skip_locked, nowait)`, `group_by(path)`.

Evaluation (one statement each, no result caching): `all()`, `first()`
(pk order when unordered), `get(where)` (exactly one row, else 0 with
"`<Model>` matching query does not exist" / "get() returned more than one
`<Model>`" in `orm_db_error`; `orm_error_is_does_not_exist`,
`orm_error_is_multiple`), `count()` (`-1` on error), `exists()`,
`aggregate(name, expr)` -> owned `char*` (0 for NULL or error, the error
text tells them apart), `aggregate_int`, `update(field, expr)`,
`update_many(list[orm_assignment*])`, `delete()` -> affected rows or `-1`.
`update`/`delete` refuse sliced querysets.

Writes (`write.w`):

- `orm_save(db, m, row)`: pk 0 -> INSERT ... RETURNING pk (and any NOT
  NULL field with a database default left null, so `status` comes back as
  `'draft'`); else UPDATE by pk, falling back to INSERT when no row has that
  pk (as Django). Returns 1, or 0 with `orm_db_error`.
- `orm_save_fields(db, m, row, list)`, `orm_delete_row` (resets the pk to
  0), `orm_refresh` (clears FK pointers whose id changed).
- `orm_bulk_create(db, m, rows, batch, orm_conflict*)`: multi-row INSERT
  ... RETURNING pk and defaults, rows per statement capped by
  `dialect.max_params`; `orm_conflict_ignore(fields)` /
  `orm_conflict_update(fields, update_fields)`. With ignore, no pks are
  stored (skipped rows return nothing).
- `orm_bulk_update(db, m, rows, fields, batch)`: `SET f = CASE WHEN pk = ?
  THEN ? ... ELSE f END WHERE pk IN (...)`.
- `orm_get_or_create` / `orm_update_or_create(db, m, lookup, defaults,
  int* created)`: lookup and defaults are `list[orm_assignment*]` (lookups
  are exact matches); both return a one-row `orm_result*`. A failed INSERT
  retries the lookup (unique race). Creation is INSERT ... RETURNING every
  column; update is UPDATE ... RETURNING, so each path is 2 statements.
- `orm_m2m_add/remove(db, m, row, field, list[void*] targets)` -> links
  added/removed; `orm_m2m_set` -> 1/0 (one DELETE of the links not wanted
  plus one INSERT ... ON CONFLICT DO NOTHING). The row's in-memory list is
  not touched. The through table is addressed through a private,
  unregistered descriptor (columns `through_from` / `through_to`); the
  through table needs a UNIQUE on that pair.
- `auto_now` is set on every save, `auto_now_add` on insert, to UTC
  `YYYY-MM-DD HH:MM:SS` (`orm_set_now(text)` pins it for tests).
  Queryset `update()` and `bulk_update` leave them alone (as Django).
  Deprecated and read-only fields are never written.

## Decisions

- **Row trailer.** Every row the ORM allocates is `struct_size` plus one
  word holding an `orm_row_meta*`: the row's annotations and the owner of
  strings the ORM writes into the row after loading (timestamps, RETURNING
  defaults, refresh). For result rows the meta lives in the result arena and
  owned strings go into `result.owned`; for `orm_row_new` rows the meta is
  on the heap and `orm_row_free` frees it. Consequently **rows passed to
  save/delete/refresh/bulk must come from `M_new()` or a result** (a stack
  `Book b` has no trailer). Generated `M_clone` must allocate with
  `orm_row_new`.
- **Annotations on model rows** are read by name:
  `orm_row_annotation(m, row, name)` / `orm_row_annotation_int`. The names
  list is shared per result.
- **values()/values_list()** load `orm_values_row` (`names`, `values`;
  `orm_values_get/at/int`, `orm_values_rows(r)`), all owned by the result.
  Plain field paths are normalized like model fields; other columns keep
  the database text.
- **Loading.** Int kinds are parsed (`sql_parse_int` / `sql_parse_bool`, so
  PostgreSQL `t/f` and SQLite `1/0` both load), text kinds copied, NULL is
  a null pointer or `__isnull = 1`. DECIMAL text is normalized to the
  field's `places` ("12.5" -> "12.50") so SQLite's numeric affinity and
  PostgreSQL agree. select_related rows are allocated in the result and
  linked into the FK slot; a related row whose pk came back NULL (LEFT JOIN
  miss) is not linked. M2M/reverse list slots are always allocated (empty)
  so typed accessors never see 0.
- **Counts.** `count()` is `SELECT COUNT(*)` unless the queryset is
  sliced, distinct, grouped, annotated or in values mode, where it counts
  the rows of the query itself (still one statement).
- **SQLite affected rows.** The SQL client reports SQLite's affected count
  as a `total_changes()` difference, which includes ON DELETE cascades and
  trigger writes. `orm_run_write` therefore adds `RETURNING pk` to SQLite
  UPDATE/DELETE and counts returned rows, so `delete()` of one author
  reports 1 on both databases. (This also caps one SQLite update/delete at
  the client's 100k-row result limit until the client uses
  `sqlite3_changes`.)
- `select_for_update` on SQLite fails before compiling with a
  "select_for_update is not supported" error.
- Query trees are not freed (nodes are shared between clones); bound-value
  scratch strings created by writes are freed after each statement.

## Limits

- No transactions here (U2.1): `bulk_create` batches are separate
  statements, and `get_or_create`'s retry assumes autocommit (inside a
  PostgreSQL transaction the failed INSERT aborts it; U2.1 adds the
  savepoint).
- `prefetch_related` is recorded only.
- bulk_create rows must all have a pk or all have pk 0.
