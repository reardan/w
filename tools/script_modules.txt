# The curated addon import root (docs/projects/scripting.md, Phase P1).
#
# bin/script_root (tools/script_root.w) copies every file listed here into
# one directory, the root an embedding host passes as an import root for
# addon code, and checks that the root is closed: each 'module' line's
# import closure, plus the runtime the compiler compiles into every
# program, resolves inside the root on x86 and x64 (no fallback to the
# upward search). Under --profile=script an addon may import only modules
# found in an import root (compiler/compiler.w, script_profile_*).
#
# Line forms (paths are repository-relative):
#   module <path>    curated: an addon may 'import' it (pure computation,
#                    text, containers, codecs; no files, processes,
#                    network, environment, clocks, threads, signals,
#                    dynamic loading or raw memory/allocator access)
#   runtime <path>   compiled by the compiler or the engine itself before
#                    any addon code (the auto-imported container runtime,
#                    lib/lib.w and the on-demand runtimes); it must ship in
#                    the root so the engine can start outside a checkout,
#                    but it is not addon API
#
# Adding a module: append a 'module' line and run './wbuild
# script_root_test'; it names every file the new module's closure pulls
# in that the root does not hold. Keep a module out when that closure
# reaches lib/file.w, lib/env.w, lib/time.w, lib/process.w, lib/thread.w,
# lib/dlcall.w, lib/net.w or anything else with an ambient capability.
